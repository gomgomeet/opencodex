# 강의 동영상 편집 툴 (lecture-video-editor 스킬) PRD

> 작성일 2026-08-12 · 개정 2026-08-13(v2: 줌 녹화 원본 + 유튜브 3종 출력 확정) ·
> 상태: 초안(리뷰 대기)

## Objective

강사(사용자 본인)가 **줌으로 녹화한** 강의 영상을 유튜브에 올릴 수 있는 완성본
3종(풀영상 / 2–3개 분할본 / 쇼츠)으로 만드는 편집 시간을, 회당 수 시간에서
30분 이내로 줄이는 편집 툴을 만든다. 형태는 별도 GUI 앱이 아니라
**Claude Code 스킬(`lecture-video-editor`) + 로컬 CLI 파이프라인(ffmpeg/Whisper)**
이다. 사용자는 자연어로 지시하고("이 줌 녹화 정리해서 유튜브용으로 3분할하고
쇼츠 5개 뽑아줘"), Claude가 분석 → 편집안 제안 → 승인 → 렌더링한다.

## 배경 / 문제

- 사용자는 교원 연수 강의를 **줌으로 녹화**하고, 이를 유튜브 채널에 올린다.
  교안(`edu-training-deck`), 강좌 소개(`edu-course-listing`),
  썸네일(`edu-thumbnail`)은 이미 스킬로 자동화되어 있으나 **가운데 공정인
  영상 편집만 수작업**으로 남아 있다.
- 수작업 편집의 병목:
  1. 줌 녹화 특유의 낭비 구간(입장 대기, "들리시나요?" 확인, 질의 공백,
     말 더듬)을 타임라인에서 눈으로 찾아 자르는 시간이 가장 크다.
  2. 자막(한국어) 생성·교정을 별도 서비스에서 다시 해야 한다.
  3. 하나의 원본에서 **풀영상·분할본·쇼츠 3종**을 각각 다시 자르고 인코딩해야
     하는데, 분할 지점과 쇼츠 후보를 매번 사람이 찾는다.
  4. 줌 화면에는 참가 교사 이름·소속·채팅이 그대로 찍혀 공개 업로드 전
     검수가 반드시 필요하다.
- 기존 스킬 조사 결과(2026-08-12): 동영상 편집/ffmpeg/자막 관련 스킬 **없음**
  → 신규 제작이 필요하다.

## 입력 전제 — 줌 녹화 원본

원본은 전부 줌 녹화이며, 이 전제가 요구사항을 크게 좌우한다.

- **파일 구성**: 로컬 녹화 시 `zoom_0.mp4`(또는 `GMT<날짜>-<시각>_Recording_*.mp4`),
  `audio_only.m4a`, `chat.txt`가 한 폴더에 생성된다. 클라우드 녹화면 자동 생성
  `*.vtt` 전사가 함께 온다. 스킬은 **폴더를 통째로 받아** 구성 요소를 자동
  인식한다(`chat.txt`는 질문 타임스탬프 힌트로만 쓰고 배포물에는 포함하지 않는다).
- **레이아웃**: 화면 공유(교안 PPT) + 발표자 썸네일이 기본. 갤러리 뷰 구간에는
  참가자 타일에 **이름·소속이 그대로 노출**된다 → F6의 1순위 검사 대상.
- **오디오**: 줌이 이미 노이즈 억제·자동 게인을 적용하고, 음소거 구간은 거의
  디지털 무음(-60dB 이하)이다. 따라서 무음 검출 임계값은 일반 캠 녹화보다
  보수적으로 잡아도 잘 맞는다(기본 `-35dB`, 최소 지속 1.5s).
- **앞뒤 낭비 구간**: 시작부의 입장 대기·음향 점검, 종료부의 인사·나가기 구간이
  거의 항상 존재한다 → 자동 트림 후보로 우선 제시한다.
- **클라우드 VTT 활용**: 있으면 전사 초안·타임코드 정렬의 시드로 쓰되,
  한국어 정확도가 낮으므로 **최종 자막은 로컬 Whisper 결과를 기준**으로 하고
  VTT는 고유명사 대조용으로만 쓴다.

## 출력 전제 — 유튜브 3종

하나의 원본에서 아래 3종을 만든다. 셋은 **같은 편집본(마스터)에서 파생**되므로
컷 편집·자막은 한 번만 하고 이후 분기한다.

| 산출물 | 규격 | 용도 |
|--------|------|------|
| **A. 풀영상** | 1920×1080 H.264, 챕터 포함 | 강의 전체 아카이브 |
| **B. 분할본 2–3개** | 동일 규격, 편당 20–40분 | 주제별 시청 유입 |
| **C. 쇼츠 3–8개** | 1080×1920 세로, 60초 이하(최대 3분) | 채널 유입·홍보 |

## 사용자 & 핵심 시나리오

대상 사용자는 1인(강사·교사). 멀티테넌시·계정 관리는 범위 외.

| # | 시나리오 | 입력 | 출력 |
|---|---------|------|------|
| S1 | 자동 컷 편집 | 줌 녹화 폴더(60–120분) | 낭비 구간 제거된 **마스터** + 컷 리스트 |
| S2 | 자막 생성 | 마스터 | 교정된 SRT/VTT (+ 쇼츠용 하드섭) |
| S3 | 챕터 + 분할 | 전사 | 유튜브 챕터 텍스트, 2–3분할 지점 제안 |
| S4 | 개인정보 검수 | 마스터 | 참가자 이름 노출 구간 리포트 + 블러/컷 |
| S5 | 3종 렌더 | 마스터 | 풀영상 1 + 분할본 2–3 + 쇼츠 3–8 |
| S6 | 업로드 메타 | 전사·챕터 | 영상별 제목·설명·태그·챕터 텍스트 초안 |

## 기능 요구사항

### P0 — MVP (풀영상까지)

- **F1. 줌 녹화 인제스트 + 자동 컷**: 녹화 폴더를 받아 구성 요소를 인식하고,
  `ffprobe` + `silencedetect` + Whisper 전사로 ① 시작·종료 낭비 구간 ② 무음
  (기본 1.5s↑) ③ 필러("어…", "음…", 반복 문장)를 찾아 **EDL(컷 리스트)을 먼저
  제안**한다. 사용자가 마크다운 표에서 승인·수정한 뒤에만 렌더링하며, 원본은
  절대 덮어쓰지 않는다(비파괴). 결과물이 **마스터**가 되고 이후 모든 산출물의
  기준이 된다.
- **F2. 한국어 자막**: faster-whisper(large-v3, 로컬)로 전사 → Claude가 교육
  용어·고유명사(지식샘터, 위두랑, 패들렛, 캔바 등)를 교정 → SRT/VTT 출력.
  용어 사전은 스킬 내 파일로 관리해 회차마다 누적한다.
- **F3. 유튜브 인코딩 프리셋**: `youtube-long`(1920×1080, H.264 CRF 18, AAC
  192k, faststart), `youtube-shorts`(1080×1920), `archive`(원본 화질 보존) 3종.
  프리셋은 설정 파일로 관리해 추가 가능. *(지식샘터 등 다른 플랫폼 프리셋은
  현재 범위에서 제외 — 배포처는 유튜브 단일.)*
- **F4. 작업 리포트**: 편집 전후 길이, 잘린 구간 수/총량, 자막 라인 수, 실행한
  ffmpeg 명령을 남겨 **동일 결과를 재현**할 수 있게 한다.

### P1 — 분할·쇼츠·검수 (실전 투입 조건)

- **F5. 챕터 + 2–3분할**: 전사에서 주제 전환 지점을 찾아 ① 유튜브 챕터 텍스트
  (`00:00`으로 시작하는 규격) ② **2–3개 분할 지점**을 제안한다. 분할은 문장
  중간을 자르지 않고 주제 경계에 맞추며, 각 편의 제목 초안과 "이전 편에서
  이어집니다" 안내 문구를 함께 생성한다. 사용자가 분할 개수·지점을 승인한 뒤
  렌더링한다.
- **F6. 개인정보 검수 (줌 특화, 배포 전 필수 게이트)**: ① 갤러리 뷰·참가자
  타일 구간을 찾아 **이름 노출 타임스탬프 리포트** ② 전사 텍스트에서 참가자
  실명·소속·연락처 호명 구간 탐지 ③ 화면 공유 중 노출된 개인정보(명단, 메신저
  알림) 후보 프레임 리포트. 처리(블러/컷/묵음)는 **사용자 확인 후** 적용한다.
  **모든 분석은 로컬에서 수행**하며 영상·음성 원본을 외부 API로 보내지 않는다.
- **F7. 쇼츠 클립 추출**: 전사에서 하이라이트(핵심 정의, 실습 팁, 인상적 한마디)
  후보를 골라 세로 1080×1920으로 재구성한다. 화면 공유 영역을 상단에 배치하고
  하단에 **큰 하드섭 자막**을 굽는다(무음 시청 대응). 편당 60초 이하를 기본으로
  하고, 후보 목록을 먼저 제시해 사용자가 고른 것만 렌더링한다.
- **F8. 인트로/아웃트로 + 썸네일 연계**: 곰곰이쌤 브랜드 인트로·아웃트로를 앞뒤에
  concat하고, 썸네일은 `edu-thumbnail` 스킬 산출물을 영상별로 연결한다.

### P2 — 업로드 마무리

- **F9. 업로드 메타데이터**: 영상 3종 각각의 제목·설명(챕터 포함)·태그 초안을
  생성하고, `edu-course-listing` 스킬로 넘길 수 있는 형태로 정리한다.
- **F10. 업로드 패키징**: 영상·자막·썸네일·설명을 업로드 순서대로 폴더에 묶고
  체크리스트를 출력한다. (유튜브 API 자동 업로드는 범위 외 — 수동 업로드 전제.)

## 비기능 요구사항

- **로컬 우선**: 영상·음성 원본은 로컬에서만 처리. LLM에는 전사 텍스트와
  메타데이터만 전달한다. 연수 참가 교사가 찍힌 녹화이므로 타협 불가 원칙.
- **비파괴**: 원본 보존, 산출물은 `output/<날짜>_<제목>/{master,full,parts,shorts}/`
  아래 생성.
- **재현성**: 모든 렌더는 EDL + ffmpeg 명령 로그로 재실행 가능해야 한다.
- **파생 일관성**: 풀영상·분할본·쇼츠는 반드시 동일 마스터에서 파생한다
  (자막·컷이 산출물마다 어긋나지 않게).
- **성능 목표**: 60분 1080p 원본 기준 전사+컷 제안까지 15분 이내(Apple Silicon
  로컬), 3종 전체 렌더는 실시간의 1배 이내.
- **의존성**: ffmpeg, faster-whisper(Python). 첫 실행 시 설치 여부를 점검하고
  없으면 설치 안내를 출력한다.

## 아키텍처 개요

```
줌 녹화 폴더 ─▶ [1] 인제스트: mp4/m4a/chat.txt/vtt 인식, ffprobe
             ─▶ [2] 분석: silencedetect + faster-whisper 전사
             ─▶ [3] 제안: 컷 리스트(EDL)·자막 교정·챕터·분할점·쇼츠 후보
             ─▶ [4] 승인: 사용자가 표에서 수정/승인 (사람 개입은 여기만)
             ─▶ [5] 마스터 렌더 (컷 적용 + 자막)
             ─▶ [6] 파생 렌더: 풀영상 / 분할본 2–3 / 쇼츠 3–8
             ─▶ [7] 개인정보 리포트 + 업로드 메타 + 작업 리포트
```

- 스킬 구조: `SKILL.md`(트리거·워크플로) + `scripts/`(인제스트·분석·렌더)
  + `presets/`(인코딩 프리셋) + `templates/`(EDL·리포트 양식)
  + `glossary/`(교육 용어 사전).
- 제작은 `skill-creator` 스킬로 진행하고, 샘플 줌 녹화 2–3개로 S1·S2 회귀
  테스트를 만든다.

## 범위

- IN: F1–F10, 스킬 패키징, 사용 가이드 문서.
- OUT: GUI 타임라인 편집기, 실시간 스트리밍 편집, 다국어 자막 번역,
  유튜브 API 자동 업로드, 클라우드 렌더팜, 유튜브 외 플랫폼 프리셋,
  이 리포(opencodex) 프록시 코어와의 코드 결합 — 본 문서는 이 리포를 작업 기록
  장소로만 사용하며 산출물 스킬은 독립 배포한다.

## 성공 지표

- 줌 녹화 60분 → 유튜브 3종(풀·분할·쇼츠) 완성까지 30분 이내, 사람 개입은
  컷 승인 + 자막 검수 + 쇼츠 선택만.
- 자막 초안 정확도: 교정 후 재수정 라인 10% 미만.
- **참가 교사 개인정보 노출 사고 0건** (업로드 전 F6 리포트 확인이 필수 게이트).

## 검증

- 샘플 줌 녹화(대기 구간·갤러리 뷰·화면 공유가 모두 포함된 10분 클립)로
  S1·S2·S4 자동 테스트.
- 실제 강의 1편으로 M3 파일럿 → 소요 시간·재수정률·쇼츠 채택률 측정 후 지표 갱신.

## 확정된 결정 (2026-08-13)

1. **녹화 소스**: 전부 줌 녹화 → 인제스트·무음 임계값·개인정보 검사(갤러리 뷰
   이름 노출)를 줌에 맞춰 특화.
2. **배포처**: 유튜브 단일 → 지식샘터 등 타 플랫폼 프리셋은 범위에서 제외.
3. **산출물**: 풀영상 + 2–3분할 + 쇼츠 3종 동시 지원 → 쇼츠(구 P2)를 P1로
   승격하고, 마스터에서 파생하는 구조로 아키텍처 변경.

## 오픈 퀘스천

1. **줌 로컬 녹화인가 클라우드 녹화인가?** 클라우드면 자동 생성 `.vtt`를 전사
   시드로 쓸 수 있어 초기 처리 시간이 줄어든다.
2. **참가 교사의 얼굴·음성이 녹화에 포함되는가?** 포함된다면 공개 업로드 전
   동의 확인 절차가 필요하고, F6에서 갤러리 뷰 구간을 컷 또는 블러 처리하도록
   기본 정책을 잡아야 한다. (화면 공유 + 강사 음성만이라면 검수 부담이 크게 준다.)
3. **인트로/아웃트로 클립 보유 여부**(F8) — 없으면 `canvas-design` 계열로 제작
   하는 하위 작업을 추가한다.
4. **분할 기본값**: 2분할과 3분할 중 기본을 무엇으로 할지, 편당 목표 길이
   (20분/30분)를 어디에 맞출지.
