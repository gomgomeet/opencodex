# 강의 동영상 편집 툴 (lecture-video-editor 스킬) PRD

> 작성일 2026-08-12 · 개정 2026-08-13(v2: 줌 녹화 원본 + 유튜브 3종 출력 확정,
> v3: 로컬 녹화·참가자 미포함·20분 분할·인트로 자체 제작 확정) ·
> 상태: 확정(M1 착수 가능)

## Objective

강사(사용자 본인)가 **줌으로 녹화한** 강의 영상을 유튜브에 올릴 수 있는 완성본
3종(풀영상 / 2–3개 분할본 / 쇼츠)으로 만드는 편집 시간을, 회당 수 시간에서
30분 이내로 줄이는 편집 툴을 만든다. 형태는 별도 GUI 앱이 아니라
**Claude Code 스킬(`lecture-video-editor`) + 로컬 CLI 파이프라인(ffmpeg/Whisper)**
이다. 사용자는 자연어로 지시하고("이 줌 녹화 정리해서 유튜브용으로 3분할하고
쇼츠 5개 뽑아줘"), Claude가 분석 → 편집안 제안 → 승인 → 렌더링한다.

## 배경 / 문제

- 사용자는 교원 연수 강의를 **줌으로 녹화**하고, 이를 유튜브 채널에 올린다.
  교안(`edu-training-deck`), 강좌 소개(`edu-course-listing`),
  썸네일(`edu-thumbnail`)은 이미 스킬로 자동화되어 있으나 **가운데 공정인
  영상 편집만 수작업**으로 남아 있다.
- 수작업 편집의 병목:
  1. 줌 녹화 특유의 낭비 구간(입장 대기, "들리시나요?" 확인, 질의 공백,
     말 더듬)을 타임라인에서 눈으로 찾아 자르는 시간이 가장 크다.
  2. 자막(한국어) 생성·교정을 별도 서비스에서 다시 해야 한다.
  3. 하나의 원본에서 **풀영상·분할본·쇼츠 3종**을 각각 다시 자르고 인코딩해야
     하는데, 분할 지점과 쇼츠 후보를 매번 사람이 찾는다.
  4. 줌 화면에는 참가 교사 이름·소속·채팅이 그대로 찍혀 공개 업로드 전
     검수가 반드시 필요하다.
- 기존 스킬 조사 결과(2026-08-12): 동영상 편집/ffmpeg/자막 관련 스킬 **없음**
  → 신규 제작이 필요하다.

## 입력 전제 — 줌 녹화 원본

원본은 전부 줌 녹화이며, 이 전제가 요구사항을 크게 좌우한다.

- **파일 구성 (로컬 녹화 기준)**: `zoom_0.mp4`(또는
  `GMT<날짜>-<시각>_Recording_*.mp4`), `audio_only.m4a`, `chat.txt`가 한 폴더에
  생성된다. 스킬은 **폴더를 통째로 받아** 구성 요소를 자동 인식한다
  (`chat.txt`는 질문 타임스탬프 힌트로만 쓰고 배포물에는 포함하지 않는다).
  클라우드 녹화 폴더가 섞여 들어와 자동 생성 `*.vtt`가 있으면 전사 시드로
  활용하되, **VTT 없이도 동작하는 것이 기본 경로**다(로컬 녹화 전제).
- **레이아웃**: 화면 공유(교안 PPT) + 발표자 썸네일. **참가자는 녹화에 포함되지
  않는다**(강사 화면·음성만) → 참가자 얼굴·이름 노출 검사는 불필요하고,
  개인정보 검수는 **화면 공유 중 우발적 노출**(알림 팝업, 명단 파일, 브라우저
  탭·북마크, 채팅창)로 범위를 좁힌다.
- **오디오**: 줌이 이미 노이즈 억제·자동 게인을 적용하고, 음소거 구간은 거의
  디지털 무음(-60dB 이하)이다. 따라서 무음 검출 임계값은 일반 캠 녹화보다
  보수적으로 잡아도 잘 맞는다(기본 `-35dB`, 최소 지속 1.5s).
- **앞뒤 낭비 구간**: 시작부의 입장 대기·음향 점검, 종료부의 인사·나가기 구간이
  거의 항상 존재한다 → 자동 트림 후보로 우선 제시한다.
- **클라우드 VTT 활용**: 있으면 전사 초안·타임코드 정렬의 시드로 쓰되,
  한국어 정확도가 낮으므로 **최종 자막은 로컬 Whisper 결과를 기준**으로 하고
  VTT는 고유명사 대조용으로만 쓴다.

## 출력 전제 — 유튜브 3종

하나의 원본에서 아래 3종을 만든다. 셋은 **같은 편집본(마스터)에서 파생**되므로
컷 편집·자막은 한 번만 하고 이후 분기한다.

| 산출물 | 규격 | 용도 |
|--------|------|------|
| **A. 풀영상** | 1920×1080 H.264, 챕터 포함 | 강의 전체 아카이브 |
| **B. 분할본 3개 내외** | 동일 규격, **편당 20분 목표** | 주제별 시청 유입 |
| **C. 쇼츠 3–8개** | 1080×1920 세로, 60초 이하(최대 3분) | 채널 유입·홍보 |

## 사용자 & 핵심 시나리오

대상 사용자는 1인(강사·교사). 멀티테넌시·계정 관리는 범위 외.

| # | 시나리오 | 입력 | 출력 |
|---|---------|------|------|
| S1 | 자동 컷 편집 | 줌 녹화 폴더(60–120분) | 낭비 구간 제거된 **마스터** + 컷 리스트 |
| S2 | 자막 생성 | 마스터 | 교정된 SRT/VTT (+ 쇼츠용 하드섭) |
| S3 | 챕터 + 분할 | 전사 | 유튜브 챕터 텍스트, 20분 단위 분할 지점 제안 |
| S4 | 화면 노출 검수 | 마스터 | 화면 공유 중 우발적 노출 구간 리포트 + 블러/컷 |
| S5 | 3종 렌더 | 마스터 | 풀영상 1 + 분할본 3 + 쇼츠 3–8 |
| S6 | 업로드 메타 | 전사·챕터 | 영상별 제목·설명·태그·챕터 텍스트 초안 |

## 기능 요구사항

### P0 — MVP (풀영상까지)

- **F1. 줌 녹화 인제스트 + 자동 컷**: 녹화 폴더를 받아 구성 요소를 인식하고,
  `ffprobe` + `silencedetect` + Whisper 전사로 ① 시작·종료 낭비 구간 ② 무음
  (기본 1.5s↑) ③ 필러("어…", "음…", 반복 문장)를 찾아 **EDL(컷 리스트)을 먼저
  제안**한다. 사용자가 마크다운 표에서 승인·수정한 뒤에만 렌더링하며, 원본은
  절대 덮어쓰지 않는다(비파괴). 결과물이 **마스터**가 되고 이후 모든 산출물의
  기준이 된다.
- **F2. 한국어 자막**: faster-whisper(large-v3, 로컬)로 전사 → Claude가 교육
  용어·고유명사(지식샘터, 위두랑, 패들렛, 캔바 등)를 교정 → SRT/VTT 출력.
  용어 사전은 스킬 내 파일로 관리해 회차마다 누적한다.
- **F3. 유튜브 인코딩 프리셋**: `youtube-long`(1920×1080, H.264 CRF 18, AAC
  192k, faststart), `youtube-shorts`(1080×1920), `archive`(원본 화질 보존) 3종.
  프리셋은 설정 파일로 관리해 추가 가능. *(지식샘터 등 다른 플랫폼 프리셋은
  현재 범위에서 제외 — 배포처는 유튜브 단일.)*
- **F4. 작업 리포트**: 편집 전후 길이, 잘린 구간 수/총량, 자막 라인 수, 실행한
  ffmpeg 명령을 남겨 **동일 결과를 재현**할 수 있게 한다.

### P1 — 분할·쇼츠·검수 (실전 투입 조건)

- **F5. 챕터 + 20분 단위 분할**: 전사에서 주제 전환 지점을 찾아 ① 유튜브 챕터
  텍스트(`00:00`으로 시작하는 규격) ② **편당 20분을 목표로 한 분할 지점**을
  제안한다. 분할 개수는 마스터 길이에서 자동 산출하되(60분→3편, 45분→2편),
  **정확히 20분에 기계적으로 자르지 않고 ±5분 범위에서 가장 가까운 주제 경계**를
  택한다(문장 중간 절단 금지). 각 편의 제목 초안과 "이전 편에 이어집니다" 안내
  문구를 함께 생성하고, 사용자가 개수·지점을 승인한 뒤 렌더링한다.
- **F6. 화면 노출 검수 (배포 전 게이트)**: 참가자가 녹화에 포함되지 않으므로
  범위를 **화면 공유 중 우발적 노출**로 한정한다 — ① 프레임 샘플링으로 알림
  팝업(메신저·메일), 명단·성적 파일, 브라우저 탭·북마크, 열려 있는 채팅창 후보를
  타임스탬프로 리포트 ② 전사 텍스트에서 실명·연락처·기관 내부 정보 호명 구간
  탐지. 처리(블러/컷/묵음)는 **사용자 확인 후** 적용한다. **모든 분석은 로컬에서
  수행**하며 영상·음성 원본을 외부 API로 보내지 않는다.
- **F7. 쇼츠 클립 추출**: 전사에서 하이라이트(핵심 정의, 실습 팁, 인상적 한마디)
  후보를 골라 세로 1080×1920으로 재구성한다. 화면 공유 영역을 상단에 배치하고
  하단에 **큰 하드섭 자막**을 굽는다(무음 시청 대응). 편당 60초 이하를 기본으로
  하고, 후보 목록을 먼저 제시해 사용자가 고른 것만 렌더링한다.
- **F8. 브랜드 모션 에셋 삽입**: 곰곰이쌤 브랜드 클립(아이보리 모눈 배경 +
  곰돌이 + 주제 카드)을 인트로·챕터 브릿지·아웃트로로 삽입한다. 상세 정책은
  아래 "브랜드 모션 에셋 활용" 절 참조. 썸네일은 `edu-thumbnail` 산출물을
  영상별로 연결한다.

### P2 — 업로드 마무리

- **F9. 업로드 메타데이터**: 영상 3종 각각의 제목·설명(챕터 포함)·태그 초안을
  생성하고, `edu-course-listing` 스킬로 넘길 수 있는 형태로 정리한다.
- **F10. 업로드 패키징**: 영상·자막·썸네일·설명을 업로드 순서대로 폴더에 묶고
  체크리스트를 출력한다. (유튜브 API 자동 업로드는 범위 외 — 수동 업로드 전제.)

## 브랜드 모션 에셋 활용 (F8 상세)

사용자가 이미 보유한 곰곰이쌤 브랜드 모션(`edu-thumbnail` 스킬이 생성하는
움직이는 썸네일 — 아이보리 모눈 배경, 곰돌이 아바타, 주제 카드가 팝업으로
등장하는 애니메이션)을 영상 편집의 브랜드 자산으로 재사용한다. **인트로·아웃트로를
새로 디자인할 필요가 없다.**

### 소스 원칙: GIF가 아니라 MP4/PNG를 쓴다

`edu-thumbnail`은 GIF(1280×720) · MP4(1920×1080) · PNG(1920×1080)를 함께
출력한다. 영상에 넣을 때는 **MP4를 소스로 쓴다.**

- GIF는 256색 팔레트 + 디더링이라, 이 브랜드의 아이보리 배경·연한 모눈처럼
  **미세한 색 계조에서 밴딩과 얼룩**이 생긴다. 유튜브 재인코딩을 거치면 더 나빠진다.
- GIF는 보통 10–15fps라 30fps 타임라인에 넣으면 움직임이 끊겨 보인다.
- GIF만 있는 경우의 폴백: `palettegen`/`paletteuse`로 팔레트를 재생성하고
  `fps=30` + `tpad`(마지막 프레임 홀드)로 보정한 뒤 사용한다. 어디까지나 차선책.

### 삽입 위치별 정책

| 위치 | 길이 | 내용 | 대상 |
|------|------|------|------|
| **인트로** | 3–5초 | 브랜드 카드 애니 + 강의 제목 | 풀영상, 분할본 |
| **챕터 브릿지** | 1.5–2초 | 주제 카드만 교체된 짧은 전환 | 풀영상 챕터 경계, 분할본 시작 |
| **아웃트로** | 5–8초 | 구독·다음 편 유도 (유튜브 엔드스크린 영역) | 풀영상, 분할본 |
| **쇼츠** | 0초 (삽입 안 함) | 필요 시 좌하단 반투명 로고 워터마크만 | 쇼츠 |

- **챕터 브릿지가 이 에셋의 최적 용도다.** 카드가 "오늘의 기사", "질문 챗봇",
  "평가 대시보드"처럼 주제 단위로 만들어져 있어 챕터 제목과 1:1로 대응된다.
  덤으로, 무음 컷 편집이 만드는 **점프컷의 어색한 이음매를 가려 준다**
  (F1의 컷 지점과 챕터 경계가 겹칠 때 우선 삽입).
- **쇼츠에는 인트로를 붙이지 않는다.** 쇼츠는 첫 1초가 이탈을 결정하는데
  3–5초 브랜드 인트로는 시청 유지율을 떨어뜨린다. 브랜딩은 워터마크로만.
- 세로(1080×1920) 변형이 필요하다. 원본 레이아웃에서 우측 카드가 세로로 길어
  세로 프레임에 재배치하기 유리하다.

### 회차마다 새로 뽑는다 (GIF를 잘라 쓰지 않는다)

카드 문구는 강의 주제마다 달라야 하므로, 기존 파일을 잘라 붙이는 대신
**`edu-thumbnail`에 제목·부제를 넘겨 회차별 클립을 생성 → concat**하는
파이프라인으로 간다. 스킬은 `assets/brand/`에 생성된 클립을 캐시하고, 같은
강의의 분할본·챕터에서 재사용한다.

### 기술 유의사항

- concat 시 **해상도·fps·픽셀 포맷·오디오 트랙을 마스터와 일치**시켜야 한다
  (브랜드 클립은 무음이므로 `anullsrc`로 무음 트랙을 붙여 concat demuxer 실패를 막는다).
- 인트로/브릿지 삽입은 **자막 타임코드를 밀어낸다.** 반드시 삽입 후 오프셋을
  재계산해 SRT를 시프트한다(F2 산출물과의 정합성 — 리포트에 검증 항목으로 포함).
- 브릿지에는 0.3초 크로스페이드(`xfade`)를 기본 적용해 급격한 전환을 피한다.

## 비기능 요구사항

- **로컬 우선**: 영상·음성 원본은 로컬에서만 처리. LLM에는 전사 텍스트와
  메타데이터만 전달한다(교육 콘텐츠 원본 보호 원칙).
- **비파괴**: 원본 보존, 산출물은 `output/<날짜>_<제목>/{master,full,parts,shorts}/`
  아래 생성.
- **재현성**: 모든 렌더는 EDL + ffmpeg 명령 로그로 재실행 가능해야 한다.
- **파생 일관성**: 풀영상·분할본·쇼츠는 반드시 동일 마스터에서 파생한다
  (자막·컷이 산출물마다 어긋나지 않게).
- **성능 목표**: 60분 1080p 원본 기준 전사+컷 제안까지 15분 이내(Apple Silicon
  로컬), 3종 전체 렌더는 실시간의 1배 이내.
- **의존성**: ffmpeg, faster-whisper(Python). 첫 실행 시 설치 여부를 점검하고
  없으면 설치 안내를 출력한다.

## 아키텍처 개요

```
줌 녹화 폴더 ─▶ [1] 인제스트: mp4/m4a/chat.txt/vtt 인식, ffprobe
             ─▶ [2] 분석: silencedetect + faster-whisper 전사
             ─▶ [3] 제안: 컷 리스트(EDL)·자막 교정·챕터·분할점·쇼츠 후보
             ─▶ [4] 승인: 사용자가 표에서 수정/승인 (사람 개입은 여기만)
             ─▶ [5] 마스터 렌더 (컷 적용 + 자막)
             ─▶ [6] 브랜드 클립 생성/캐시 (edu-thumbnail 연계)
             ─▶ [7] 파생 렌더: 풀영상 / 분할본 3 / 쇼츠 3–8 (+ 자막 오프셋 재계산)
             ─▶ [8] 노출 검수 리포트 + 업로드 메타 + 작업 리포트
```

- 스킬 구조: `SKILL.md`(트리거·워크플로) + `scripts/`(인제스트·분석·렌더)
  + `presets/`(인코딩 프리셋) + `templates/`(EDL·리포트 양식)
  + `glossary/`(교육 용어 사전) + `assets/brand/`(회차별 브랜드 클립 캐시).
- 제작은 `skill-creator` 스킬로 진행하고, 샘플 줌 녹화 2–3개로 S1·S2 회귀
  테스트를 만든다.

## 범위

- IN: F1–F10, 스킬 패키징, 사용 가이드 문서.
- OUT: GUI 타임라인 편집기, 실시간 스트리밍 편집, 다국어 자막 번역,
  유튜브 API 자동 업로드, 클라우드 렌더팜, 유튜브 외 플랫폼 프리셋,
  이 리포(opencodex) 프록시 코어와의 코드 결합 — 본 문서는 이 리포를 작업 기록
  장소로만 사용하며 산출물 스킬은 독립 배포한다.

## 성공 지표

- 줌 녹화 60분 → 유튜브 3종(풀·분할 3편·쇼츠) 완성까지 30분 이내, 사람 개입은
  컷 승인 + 자막 검수 + 쇼츠 선택만.
- 자막 초안 정확도: 교정 후 재수정 라인 10% 미만.
- **화면 공유 중 개인정보 노출 사고 0건** (업로드 전 F6 리포트 확인이 필수 게이트).
- 브랜드 클립 삽입 후 **자막 싱크 어긋남 0건** (오프셋 재계산 자동 검증).

## 마일스톤

| 단계 | 내용 | 완료 기준 |
|------|------|-----------|
| M1 | 스킬 골격 + F1(줌 인제스트·무음 컷) | 샘플 줌 녹화에서 EDL 제안→승인→마스터 렌더 성공 |

## 검증

- 샘플 줌 녹화(대기 구간·화면 공유·알림 팝업이 포함된 10분 클립)로
  S1·S2·S4 자동 테스트.
- 브랜드 클립 삽입본에서 자막 싱크 회귀 테스트(삽입 전후 SRT 타임코드 비교).
- 실제 강의 1편으로 M3 파일럿 → 소요 시간·재수정률·쇼츠 채택률 측정 후 지표 갱신.

**2026-08-13 (v3)**

   설계하고, VTT가 있으면 보조로만 활용한다.
5. **참가자 미포함**: 강사 화면·음성만 녹화되므로 갤러리 뷰 이름 노출·동의

6. **분할 기준 20분**: 마스터 길이에서 편수를 자동 산출(60분→3편)하되 ±5분
   범위의 주제 경계에 맞춰 자른다.
7. **인트로/아웃트로 신규 제작 불필요**: 보유한 곰곰이쌤 브랜드 모션

   단 GIF가 아닌 MP4를 소스로 쓰고, 회차마다 새로 생성해 concat한다.

유사한 강의 편집 워크플로(수동 프롬프트 방식, 6회 실패 끝에 완주한 실전 기록)와
비교 분석해 도출한 보완점. 우선순위 순.

| # | 항목 | 내용 | 반영 위치 |
|---|------|------|-----------|
| B1 | **VFR 정규화** | 줌 로컬 녹화가 가변 프레임레이트면 컷 결과물이 재생 불가할 수 있음. ingest에서 VFR 감지 → 마스터 렌더 때 fps 정규화 | M1.1 (즉시) |
| B2 | **freezedetect 교차 검증** | 무음이어도 화면이 움직이면(시연 중) 자동 컷 금지. 무음 ∩ 화면정지 70% 이상만 자동 컷, 나머지는 '확인 필요(C)'로 분류 | M3 → M1.1로 승격 |

## 오픈 퀘스천

M1 착수를 막는 항목은 없다. 아래는 구현하며 확정한다.

1. **브랜드 클립 원본 형식**: `edu-thumbnail`이 실제로 남긴 MP4 원본이 남아
   있는지, GIF만 보관 중인지 — GIF만 있으면 팔레트 재생성 폴백 경로를 먼저
   구현해야 한다(M1에서 확인).
2. **쇼츠 세로 레이아웃**: 화면 공유 영역을 상단에 두고 하단 자막을 크게 굽는
   기본안 외에, 강사 캠 썸네일을 함께 넣을지 여부 — 파일럿에서 실제 화면
   구성을 보고 결정.
3. **아웃트로 CTA 문구**: 구독 유도 / 다음 편 안내 / 채널 링크 중 무엇을 넣을지
   (유튜브 엔드스크린 요소 배치와 함께 M4에서 확정).
