# 강의 카드뉴스(캐러셀) 생성 스킬 — 구상

> 작성일 2026-08-13 · 개정(인스타+블로그 동시, 화면 캡처 포함, 8장 확정) ·
> 상태: 구상 확정(C1 착수 가능)

## 왜 만드나

강의 하나에서 나오는 산출물이 지금은 유튜브 3종(풀영상·분할본·쇼츠)뿐이다.
여기에 **카드뉴스(캐러셀)** 를 더하면 인스타·블로그·스레드로 유입 경로가 넓어지고,
영상을 볼 시간이 없는 선생님들에게도 내용이 닿는다.

핵심은 **재료가 이미 있다는 것**이다. `lecture-video-editor`가 M2에서 만드는
전사 텍스트에 강의 내용이 통째로 들어 있으므로, 카드뉴스는 새로 쓰는 게 아니라
**뽑아내는** 작업이 된다.

```
줌 녹화 ─▶ lecture-video-editor ─┬─▶ 유튜브 풀영상 / 분할본 / 쇼츠
                                  ├─▶ 전사 ────┐
                                  └─▶ 마스터 ──┤
                                               ▼
                                        edu-carousel ─┬─▶ 인스타 카드 8장
                                                      └─▶ 블로그 글 + 이미지
```

## 산출물 — 인스타와 블로그를 함께 낸다

둘 다 운영하므로 **한 번 만든 내용에서 두 플랫폼 산출물을 파생**한다.
영상에서 마스터 하나로 3종을 뽑는 것과 같은 원칙이다 — 내용을 두 번 쓰면 어긋난다.

| 산출물 | 규격 | 비고 |
|--------|------|------|
| **인스타 카드** | PNG 1080×1350 (4:5), **8장** | 피드 세로 점유가 가장 큰 비율 |
| **인스타 캡션** | 본문 + 해시태그 + 링크 | 첫 2줄에 후킹 (더보기 전에 보이는 부분) |
| **블로그 본문** | 마크다운 | 소제목 구조로 — 검색 유입은 이미지가 아니라 **텍스트**가 만든다 |
| **블로그 이미지** | 카드 재사용 (기본) / 가로 1200×675 (선택) | 네이버 블로그 본문 폭에 맞음 |
| **대체 텍스트** | 카드별 alt 문구 | 접근성 |

블로그에 카드 이미지만 올리면 검색에 잡히지 않는다. **같은 내용을 글로도 풀어 쓰는 것**이
블로그 트랙의 핵심이고, 전사가 있으니 이건 거의 공짜로 나온다.

인스타 캐러셀은 최대 20장까지 되지만 완독률을 보면 8장 안팎이 적정이다.

## 카드 구성 공식

매번 같은 뼈대를 쓴다 — 브랜드 일관성이 생기고, 자동 생성도 쉬워진다.

| # | 역할 | 내용 |
|---|------|------|
| 1 | **후킹 표지** | 질문형 제목 ("아직도 학기말에 몰아서 기록하세요?") |
| 2 | 공감 | 선생님들이 실제로 겪는 문제 상황 |
| 3–6 | **핵심** | 한 장에 한 메시지. 이 중 **2–3장은 실제 강의 화면 캡처** |
| 7 | 실천 | 당장 해볼 수 있는 한 가지 |
| 8 | **마무리 CTA** | 강좌 안내 · 유튜브 전체 영상 링크 · 팔로우 유도 |

### 글자 수 상한 (모바일 가독성)

| 위치 | 상한 |
|------|------|
| 표지 제목 | 18자 (2줄 이내) |
| 본문 카드 제목 | 20자 |
| 본문 설명 | 70자 |

상한을 넘으면 **줄여 쓰지 말고 카드를 나눈다.** 작은 화면에서 글자가 빽빽한 카드는
그냥 넘겨진다. 초과 시 스킬이 분할안을 제안하고 사용자가 고른다.

## 강의 화면 캡처 — 마스터 영상에서 뽑는다

"실제로 이렇게 생겼습니다"를 보여주는 캡처 카드가 설득력을 만든다. 별도로 스크린샷을
찍어 모으지 않고, **이미 만들어 둔 마스터 영상에서 프레임을 추출**한다.

```
ffmpeg -ss <타임스탬프> -i master.mp4 -frames:v 1 -q:v 2 capture.png
```

- **후보 선정**: 전사에서 "여기 보시면", "이 화면에서" 같은 지시 표현이 나오는
  시점을 찾아 캡처 후보로 제안한다. 사용자가 고른 것만 추출한다.
- **배치**: 화면 캡처는 16:9라 4:5 카드에 그대로 넣으면 위아래가 빈다. 캡처를 상단에
  두고 하단에 설명 문구를 배치하는 전용 레이아웃을 쓴다. 캡처 영역은 라운드 처리 +
  옅은 테두리로 카드 배경과 구분한다.
- **가독성**: 강의 화면의 작은 글씨는 인스타에서 안 보인다. 캡처를 통째로 넣지 말고
  **필요한 영역만 잘라 확대**하는 것을 기본으로 한다(크롭 좌표를 함께 제안).

### 노출 검수는 필수 게이트다

캡처를 넣기로 한 이상, 이건 선택이 아니다. 영상은 스쳐 지나가지만 **캡처 이미지는
멈춰 있어서 누구나 확대해 볼 수 있다.**

추출한 캡처마다 알림 팝업·명단·브라우저 탭·북마크·다른 창의 개인정보가 찍히지
않았는지 확인하고, **사용자에게 이미지를 보여준 뒤 승인받는다.** 승인 전에는
카드에 넣지 않는다. 가릴 부분이 있으면 해당 영역만 블러 처리한다.

이 검수는 `lecture-video-editor` M3의 화면 노출 검수와 같은 로직을 쓰므로,
**그쪽을 먼저 구현하고 여기서 재사용**한다.

## 브랜드

`edu-thumbnail`의 곰곰이쌤 시스템을 그대로 쓴다 — 새 디자인 언어를 만들지 않는다.

- 아이보리 모눈 배경, Pretendard 서체
- 곰돌이 아바타는 **표지와 마무리에만** (본문마다 넣으면 내용 자리를 잡아먹는다)
- 강조색: 초록(개념) · 파랑(도구) · 빨강(주의) — 카드 상단 배지로 구분

## 생성 방식 — HTML + Playwright 권장

| 방식 | 장점 | 단점 |
|------|------|------|
| **HTML/CSS → Playwright 스크린샷** | 픽셀 단위 제어, 반복 생성 일관, 무료·로컬, 버전 관리 가능 | 디자인 수정에 코드 필요 |
| Canva MCP | 사용자가 직접 손보기 쉬움, 템플릿 자산 활용 | 자동 생성 일관성 떨어짐, 외부 전송 |
| Python(PIL) | 의존성 가벼움 | 한글 줄바꿈·자간 처리가 조악함 |

**HTML + Playwright를 기본으로 한다.** 카드뉴스는 같은 틀에 내용만 바뀌는 반복 작업이라
템플릿 방식이 가장 잘 맞고, 렌더 환경(Chromium)이 이미 깔려 있다.

### 폰트를 반드시 동봉해야 한다

이 환경에서 확인한 결과 **Pretendard가 설치돼 있지 않다**(한글 폰트가 Unifont·문쿠안이
정도뿐). 시스템 폰트에 의존하면 컴퓨터마다 결과가 달라지고, 최악의 경우 한글이 깨진다.

→ 폰트 파일을 스킬에 넣고 `@font-face`로 임베드한다. 그러면 윈도우·맥·리눅스
어디서 돌려도 **글자 하나까지 동일한 결과**가 나온다. (웹폰트 라이선스 확인 필요 —
Pretendard는 OFL로 재배포 가능.)

### Canva는 "손보고 싶을 때"의 선택지로

기본 경로는 HTML로 뽑되, 사용자가 직접 수정하고 싶다고 하면 Canva로 넘기는
하이브리드로 둔다. 다만 강의 화면 캡처가 들어간 카드는 외부 업로드 전에
노출 검수를 먼저 거친다.

## 입력

세 가지를 모두 받는다.

1. **강의 전사 + 마스터 영상** (`lecture-video-editor` 산출물) — 주 경로
   (전사는 문구의 재료, 마스터는 캡처의 재료)
2. **교안 pptx** (`edu-training-deck` 산출물)
3. **그냥 주제 한 줄** — 강의 없이 단독 제작 (캡처 없이)

## 워크플로

1. 재료 받기 (전사·마스터 / 교안 / 주제)
2. **카드 문구 초안을 텍스트로 먼저 제안** — 이미지 렌더 전에 승인받는다
   (렌더는 몇 초지만, 문구가 틀리면 전부 다시 뽑아야 하므로)
3. **캡처 후보 제안 → 노출 검수 → 승인** (캡처 카드가 있을 때만)
4. 승인 후 인스타 카드 PNG 렌더
5. 같은 내용으로 블로그 본문 글 생성
6. 캡션 · 해시태그 · alt 텍스트 생성
7. 플랫폼별 업로드 폴더로 묶기

`lecture-video-editor`와 같은 원칙을 따른다 — **승인 후 생성, 비파괴, 로컬 우선.**
사람이 개입하는 지점은 두 곳(문구 승인, 캡처 승인)뿐이다.

## 범위

- IN: 카드 템플릿, HTML 렌더, 전사·교안 연계, 마스터 영상 캡처 추출,
  블로그 본문 생성, 캡션·해시태그·alt
- OUT: 자동 업로드(인스타·블로그 API), 동영상 캐러셀, 다국어,
  유료 폰트·이미지 사용

## 마일스톤

| 단계 | 내용 | 완료 기준 |
|------|------|-----------|
| C1 | 템플릿 + HTML 렌더 + 폰트 임베드 | 주제 한 줄 → 인스타 카드 8장 PNG |
| C2 | 전사 연계 자동 초안 + 블로그 본문 | 강의 전사 → 카드 문구 + 블로그 글 |
| C3 | 캡처 추출 + 노출 검수 + 캡처 카드 레이아웃 | 마스터에서 캡처 뽑아 카드에 배치 |
| C4 | 캡션·해시태그·alt + 업로드 폴더 패키징 | 인스타·블로그 동시 완성 |
| C5 | Canva 연동(선택) | 초안을 Canva로 넘겨 직접 수정 |

C3은 `lecture-video-editor` M3(화면 노출 검수)에 의존한다 — 그쪽을 먼저 만든다.

## 확정된 결정 (2026-08-13)

1. **인스타 + 블로그 둘 다** — 한 내용에서 두 산출물을 파생한다. 블로그는 이미지만
   올리지 않고 **본문 글을 함께 생성**한다(검색 유입은 텍스트가 만든다).
2. **강의 화면 캡처 포함** — 마스터 영상에서 프레임을 추출해 쓴다. 대신
   **노출 검수를 필수 게이트**로 둔다(정지 이미지는 확대해 볼 수 있으므로 영상보다 위험).
3. **8장 고정** — 표지 1 + 공감 1 + 핵심 4(그중 캡처 2–3) + 실천 1 + CTA 1.

## 남은 판단 (구현하며 정함)

- 블로그 이미지를 카드 그대로 쓸지, 가로 1200×675로 재배치할지 — C2에서 실제
  블로그에 올려 보고 결정.
- 캡처 크롭을 자동 제안할지(화면에서 텍스트 밀집 영역 탐지), 사용자가 지정할지.
