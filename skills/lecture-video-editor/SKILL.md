# 강의 동영상 편집 (lecture-video-editor)

줌 녹화 → 유튜브 3종(풀영상 / 20분 분할본 / 쇼츠)을 만드는 편집 파이프라인.

## 핵심 원칙 — 반드시 지킬 것

1. **비파괴**: 원본을 절대 덮어쓰지 않는다. 모든 산출물은 별도 출력 폴더에 만든다.
2. **승인 후 렌더**: 컷 리스트(EDL)를 표로 먼저 보여주고 사용자가 승인한 뒤에만
   렌더링한다. 자동으로 잘라 버리지 않는다.
3. **로컬 처리**: 영상·음성 원본을 외부 API로 보내지 않는다. 전사 텍스트와
   메타데이터만 다룬다. (교육 콘텐츠 보호 원칙 — 타협 금지)
4. **마스터 단일 원본**: 풀영상·분할본·쇼츠는 모두 하나의 마스터에서 파생한다.
   산출물마다 따로 자르면 자막이 어긋난다.
5. **실패는 기록한다**: 작업 중 실패를 만나면 원인·대응을 `TROUBLESHOOTING.md`에
   추가한다(최신이 위). 새 실패를 진단하기 전에 그 파일을 먼저 읽는다 —
   이미 겪은 문제일 수 있다.

## 사전 확인

`ffmpeg`, `ffprobe`가 필요하다. 없으면 설치를 안내하고 중단한다.

```bash
ffmpeg -version    # 없으면: macOS `brew install ffmpeg` / Ubuntu `sudo apt-get install ffmpeg`
```

자막 단계(M2~)는 추가로 `faster-whisper`가 필요하다.

## 워크플로

작업 폴더는 `skills/lecture-video-editor/scripts` 기준으로 실행한다.
출력 폴더(`-o`)를 지정하지 않으면 녹화 폴더 옆에 `_lve_output/`이 생긴다.

### 1단계 — 인제스트

사용자에게 줌 녹화 폴더 경로를 받는다. 보통 이런 위치다:

- macOS: `~/Documents/Zoom/2026-08-13 10.00.00 강의제목/`
- Windows: `C:\Users\<사용자>\Documents\Zoom\...`

```bash
python3 ingest.py "<녹화폴더>" -o "<출력폴더>"
```

`zoom_0.mp4`(본 영상), `audio_only.m4a`(분석 가속), `chat.txt`(질문 시점 힌트),
`*.vtt`(클라우드 녹화면)를 자동 인식해 `manifest.json`을 만든다.
영상이 여러 개면 가장 큰 파일을 본 영상으로 고른다 — 결과를 사용자에게 알리고,
다르면 파일을 직접 지정받는다.

### 2단계 — 무음 분석

```bash
python3 analyze.py "<출력폴더>/manifest.json"
```

`audio_only.m4a`가 있으면 그것으로 무음을 분석한다(빠름). 임계값 기본 `-35dB` —
줌은 노이즈 억제가 이미 적용되어 이 값으로 잘 잡힌다.

이어서 **화면 정지 분석(freezedetect)** 이 자동으로 돈다 — 무음이어도 화면이
움직이면(말 없이 시연 중) 자르면 안 되기 때문이다. 이건 영상 전체를 디코딩하므로
시간이 걸린다(60분 영상 기준 수 분). 급하면 `--no-freeze`로 끌 수 있지만, 그러면
시연 구간이 잘릴 위험을 사용자에게 알려야 한다.

결과는 `analysis.json`. **이 단계가 가장 오래 걸리므로 한 번만 실행한다.**

### 3단계 — 컷 리스트 제안 (사람이 개입하는 지점)

```bash
python3 plan_cuts.py "<출력폴더>/analysis.json"
```

`edl.md`(승인용 표)와 `edl.json`을 만든다. **`edl.md` 표를 사용자에게 그대로
보여주고 승인을 받는다.** 컷이 20개를 넘으면 전부 나열하지 말고 요약
(총 개수·단축 시간·종류별 분포)과 상위 10개만 보여준 뒤 전체 파일 경로를 안내한다.

컷은 화면 정지와 교차 검증해 두 가지로 분류된다:
- **자동**: 무음 + 화면 정지 (70% 이상 겹침) → 기본으로 잘린다
- **확인 필요**: 무음이지만 화면이 움직임 → **시연 중일 수 있으므로 기본으로
  자르지 않는다.** 사용자에게 해당 시점을 영상에서 확인하도록 안내하고,
  잘라도 된다고 하면 `--confirm-cuts <번호>`로 포함한다.

'확인 필요'가 컷의 대부분이면 경고가 뜬다 — 웹캠 썸네일처럼 화면 일부가 항상
움직이는 녹화다. 이때는 `--ignore-freeze`로 교차 검증을 끄는 것을 제안한다.

사용자 요청에 따라 다시 제안한다 (분석은 재실행 불필요, 즉시 끝난다):

| 사용자 말 | 실행 |
|-----------|------|
| "3번, 7번은 살려줘" | `--keep-cuts 3,7` |
| "3번도 잘라줘" (확인 필요 컷 승인) | `--confirm-cuts 3` |
| "무음 2초 이상만 잘라줘" | `--min-silence 2.0` |
| "너무 급하게 끊겨" | `--pad 0.4` (여백을 늘린다) |
| "시작 부분은 그대로 둬" | `--head-threshold 9999` |

주요 옵션: `--min-silence`(자를 무음 최소 길이, 기본 1.5s), `--pad`(앞뒤 여백,
기본 0.25s), `--min-cut`(이보다 짧은 컷은 무시, 기본 0.5s).

### 4단계 — 마스터 렌더

승인을 받은 뒤에만 실행한다.

```bash
python3 render_master.py "<출력폴더>/edl.json" --preset master
```

`select/aselect` 필터로 통과시켜 프레임 단위로 정확히 자른다. 남길 구간이 80개를
넘으면 ffmpeg 표현식 파서 한계(between() 항 100개 부근에서 `Cannot allocate memory`)에
걸리므로 자동으로 패스를 나눠 렌더한 뒤 재인코딩 없이 이어붙인다 — 묶음 경계는 항상
컷 사이라 프레임 손실이 없다. 한 패스에 넣을 구간 수는 `--max-terms`로 조정한다.
결과는 `master/<이름>_master.mp4`, 로그는 `render_master_log.json`.
렌더 후 실제 길이와 예상 길이를 비교해 **1초 이상 어긋나면 경고**한다 — 이때는
EDL을 다시 확인한다.

빠르게 확인만 할 때는 `--preset draft`(720p 저화질), 명령만 볼 때는 `--dry-run`.

### 5단계 — 전사 (M2)

```bash
python3 transcribe.py "<출력폴더>/manifest.json"          # 기본 large-v3, 로컬 처리
```

faster-whisper로 한국어를 **단어 단위 타임스탬프**와 함께 전사해 `transcript.json`을
만든다. 첫 실행은 모델 다운로드(large-v3 약 3GB)가 필요하다. 메모리가 부족하거나
급하면 `--model medium`. **음성은 절대 외부 API로 보내지 않는다.**

전사가 끝나면 교육 용어·고유명사(지식샘터, 위두랑, 패들렛 등) 오인식을 교정한다 —
transcript.json의 해당 단어를 직접 수정하고, 자주 틀리는 용어는 기억해 둔다.

### 6단계 — 컷 정밀 보정 (전사 기반)

```bash
python3 refine_cuts.py "<출력폴더>/edl.json"
```

두 가지를 한다. **반드시 3단계 승인 → 이 단계 → 렌더 순서**로 간다:
- **경계 스냅**: 한국어는 어미를 작게 발음해 무음 검출이 말끝을 먹는다
  ("그렇습니다"→"그렇니다"). 컷 경계가 단어를 자르면 단어 밖으로 밀어낸다.
- **반복 어절**: 말 더듬어 같은 말을 두 번 한 곳(인접 1~6어절)을 찾아 첫 발화만
  컷으로 추가한다. 딱 붙은 반복만 자동, 간격이 있으면 확인 필요로 분류 —
  사용자에게 물어보고 `--confirm-cuts`로 처리한다. **문장 전체를 지우지 않는다.**

### 7단계 — 자막 + 완성 대본

```bash
python3 make_subtitles.py "<출력폴더>/edl.json"
```

컷으로 사라진 시간만큼 타임코드를 재계산해 `subtitles/master.srt`를 만들고,
검수용 `final_script.md`를 생성한다. **렌더 전에 대본을 사용자에게 보여주고
처음부터 끝까지 읽게 한다** — 끊긴 문장, 남은 반복, 잘못 잘린 말끝은 눈으로
읽어야 보인다. 대본 승인 후 4단계(마스터 렌더)를 실행한다.

### 인코딩 프리셋

`presets/encode.json`에서 관리한다.

| 프리셋 | 용도 |
|--------|------|
| `master` | 마스터(CRF 16) — 파생본의 원본 |
| `youtube-long` | 풀영상·분할본 1920×1080 CRF 18 |
| `youtube-shorts` | 쇼츠 1080×1920 세로 |
| `draft` | 720p 저화질 검수용 (배포 금지) |

## 진행 상황

- **구현 완료 (M1)**: 인제스트(VFR 감지) → 무음+화면정지 분석 → 컷 제안(분류·승인)
  → 마스터 렌더(CFR 정규화·분할 렌더)
- **구현 완료 (M2)**: 전사(단어 타임스탬프) → 컷 경계 스냅·반복 어절 → SRT 재계산
  → 완성 대본 검수
- **다음 (M3~)**: 20분 분할, 쇼츠 추출, 화면 노출 검수, 브랜드 모션 삽입,
  업로드 메타데이터

미구현 기능을 요청받으면 아직 없다고 알리고, 현재 가능한 범위를 먼저 처리한 뒤
다음 단계를 안내한다. 없는 기능을 있는 것처럼 말하지 않는다.

### 전체 순서 요약

```
ingest → analyze → plan_cuts → [컷 승인] → transcribe → refine_cuts
       → make_subtitles → [대본 검수] → render_master
```

## 주의사항

- **오디오 트랙이 없으면** 무음 분석이 불가능하다. 인제스트에서 경고한다.
- **화면 공유 중 노출**(알림 팝업, 명단, 브라우저 탭)은 M3의 검수 기능이 붙기
  전까지 사용자가 직접 확인해야 한다. 업로드 전에 이 점을 반드시 안내한다.
- **브랜드 클립을 앞에 붙이면 자막 타임코드가 밀린다.** M3~에서 삽입 기능을
  구현할 때 SRT 오프셋 재계산을 반드시 함께 처리한다.
- 렌더는 CPU를 오래 쓴다. 60분 영상 기준 실시간의 3~6배속(약 10~20분)이 정상이다.
