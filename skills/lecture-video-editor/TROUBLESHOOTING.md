# 실패 기록 (TROUBLESHOOTING)

**규칙: 실패하면 원인과 대응을 여기에 계속 추가한다.** 쌓일수록 같은 실수를 반복하지
않는다. 항목은 최신이 위. 형식: 증상 → 원인 → 대응 → 재발 방지.

## 2026-08-13 · 컷 100개 초과 시 마스터 렌더 사망

- **증상**: 55분 강의(컷 147개) 렌더 중 ffmpeg이 `Cannot allocate memory`로 죽음.
- **원인**: select 필터의 between() 항 수에 빌드별 한계가 있음.
  윈도우 빌드 실측 100 OK / 120 FAIL. (Ubuntu 6.1.1은 2000개도 통과 —
  **빌드마다 다르므로 보편 한계로 취급하지 말 것**.)
- **대응**: 구간이 `--max-terms`(기본 80)를 넘으면 패스를 나눠 렌더 후
  concat 디먹서로 무손실 결합. `render_master.py`에 구현, 회귀 테스트 6단계 추가.
- **재발 방지**: 가장 빡빡한 환경(윈도우)에 맞춘 80을 기본값으로 유지.
  분할 비용은 concat이 재인코딩 없음이라 사실상 0.

## 2026-08-13 · 한글 윈도우에서 테스트가 완주 못 함

- **증상**: `run_pipeline_test.py`가 마지막 검증에서 AttributeError로 사망,
  stderr가 None.
- **원인**: subprocess에 `text=True`만 주면 로케일 코드페이지(cp949)로 디코딩.
  ffmpeg의 UTF-8 출력을 만나면 리더 스레드가 죽음.
- **대응**: 모든 subprocess 호출에 `encoding="utf-8", errors="replace"` 명시.
- **재발 방지**: 새 스크립트를 만들 때 subprocess 호출은 반드시
  `lve/common.py`의 `run()`을 쓰거나 동일 인자를 명시한다.

## (예방 등록) 줌 로컬 녹화는 VFR일 수 있음 — 컷 전 fps 정규화 필요

- **증상(외부 사례)**: 컷 편집 결과물이 재생 불가. 6회 연속 실패, 원인 규명에 4시간.
  "fps 30 고정 후 자르기"로 해결됨.
- **원인(추정)**: 줌 로컬 녹화가 가변 프레임레이트(VFR)인 경우, 타임스탬프 기반
  컷/concat에서 PTS가 꼬임. 우리 테스트 픽스처는 CFR 30fps라 이 경로를 못 봄.
- **대응(예정)**: ingest에서 `r_frame_rate` vs `avg_frame_rate` 불일치로 VFR을
  감지해 manifest에 기록하고, VFR이면 마스터 렌더 때 `fps=30`을 필터 앞단에 넣어
  정규화한다.
- **주의**: 같은 사례에서 나온 `baseline 프로파일/-bf 0` 처방은 베끼지 말 것 —
  원인(VFR)과 무관한 우연 요소일 가능성이 높고, 유튜브 업로드엔 high 프로파일이
  표준이며 baseline은 압축 효율만 희생한다.
